# Troubleshooting Index

Use this file when a user reports a problem or asks why GoCluster behaved a
certain way. This is a routing layer, not the source of truth. Cite this file,
then cite the underlying repo docs or TSRs.

## Replay deadlines

If identical target reports yield different replay corrections after changing
unrelated traffic, check the replay tool version and temporal decision time.
Scheduled holds must release at their lag/max-wait deadlines before later
samples can expire evidence. The traffic invariant excludes capacity pressure
and changed relevant evidence. Equal timestamps use sample, release, incoming
rows. EOF retains its existing forced-retirement clock. See the
[replay contract](https://raw.githubusercontent.com/N2WQ/GoCluster/main/docs/rbn_replay.md#determinism-model)
and [TSR-0101](https://raw.githubusercontent.com/N2WQ/GoCluster/main/docs/troubleshooting/TSR-0101-replay-deadline-scheduling.md).
Replay metrics may change after the repair; this does not imply changed live
latency or improved RF accuracy.

## Rules

- Use the most specific matching symptom route. Platform-specific routes beat
  generic routes when the user has already named Windows, Linux, service mode,
  telnet, or another concrete surface.
- If the user asks how to troubleshoot after naming a symptom, give an ordered
  diagnostic procedure first. Ask only for evidence that changes the next step,
  and show the concrete command or file to inspect when the docs support one.
- Ask for the exact symptom, command, config path, and log text when those
  details are still missing.
- For config-sensitive answers, tell the user to check the effective YAML loaded
  through `DXC_CONFIG_PATH`.
- For service issues, prefer local `systemctl` and `journalctl` output before
  guessing.
- For spot-output issues, check per-user telnet state before assuming ingest
  failure.
- For old incidents, route to [docs/troubleshooting-log.md](https://raw.githubusercontent.com/N2WQ/GoCluster/main/docs/troubleshooting-log.md) and the matching
  TSR. Use the TSR `RCA Summary` as the first-pass explanation, then verify
  current docs or code before treating the TSR as current behavior.
- Do not invent config keys, command syntax, error messages, source behavior, or
  default values.

## Evidence To Ask For

- Exact command typed, including telnet dialect if known.
- Exact startup error, log line, or telnet response.
- Active config directory from `DXC_CONFIG_PATH`.
- Relevant YAML snippet with secrets removed.
- Current system log startup block, including `Config warning`, H3 validation,
  and gridstore lines when startup fails.
- `SHOW FILTER RULE` or `SHOW FILTER FULL`, `SHOW SETTINGS`, `SHOW HOLD`, `SHOW DEDUPE`,
  `SHOW BUILD`, and `SET DIAG <mode>` output when
  the issue is telnet-visible.
- For client configuration failures: the canonical command, request ID, framed
  error and a redacted writable payload; actual LF/CRLF body-byte count and
  elapsed upload time for framing/size errors. Do not request private user
  records or silently replay a stale PUT/PATCH. Read with
  `GET YAML CONFIG SCHEMA 5` or `GET YAML FILTER SCHEMA 5` when pause-neutral
  inspection is needed; all machine success/errors leave pause state alone.
- `systemctl status gocluster` and `journalctl -u gocluster -n 200 --no-pager`
  for Linux service failures.

PC92 controlled retries, required `peering.max_peers`, and recovery phase diagnostics: [peer bulletin/dedupe support card](support-cards/peer-bulletin-dedupe.md), [v14 evidence](../docs/pc92-v14-validation.md).

For changed regional p50, shared-bucket counts, common-resolution selection or
fine fallback after stale coarse evidence, start with
`docs/decisions/ADR-0308-path-population-identity.md`,
`pathreliability/candidate_query.go` and the path-reliability support card.

Recent path-support failures use decay-adjusted usable/admitted report units,
not lifetime `n` diagnostics. See [ADR-0309](../docs/decisions/ADR-0309-recent-report-support-and-receiver-units.md)
and [the path support card](support-cards/path-reliability.md) for `/u` and
receiver qualification. CLOSED precedence is unchanged.
