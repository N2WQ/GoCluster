# ADR-0242: Release Preparation Safety

- Status: Accepted
- Date: 2026-10-04
- Decision Origin: Troubleshooting chat

## Context

Release preflight hid the Git paths responsible for dirty-worktree refusal.
Windows checkout conversion could produce Git-clean CRLF checksum files that
`go mod tidy -diff` rejected. The release script also removed unverified output
directories before compilation, left process build settings changed, and did
not bind all publication operations to the captured source commit and selected
Git remote. Codex's checker unconditionally rejected release-script edits even
when separately approved under its normal Non-trivial gate.

## Decision

Preserve ADR-0078's initial comprehensive clean-source and read-only tidy gates,
including package-only exceptions. Display offending Git status paths. Root
module files use LF through repository attributes without dependency changes.

Prepare one package in an invocation-owned ignored temporary directory before
replacing any output. Custom single-component package names and custom ZIP
output directories remain supported. Reject source collisions, Windows aliases,
reserved names, traversal, unsafe ancestry, and reparse points. Replacement
requires a generated ownership manifest with unchanged files, directories, and
ZIP hash. Refuse legacy, incomplete, operator-modified, and unrelated outputs.
Write the private manifest after archiving; it does not enter the public ZIP.
Eliminate automatic deletion of legacy nested staging. Retain recoverable prior
outputs during promotion and report recovery paths if rollback fails.
If backup verification or disposal fails, preserve the invocation directory
and report the remaining backup paths instead of deleting unverified contents.

Before refs are created, recheck HEAD and source status. Only verified untracked
outputs generated by this invocation may be excluded from the final status
check. Existing custom outputs remain subject to the initial clean-source gate.
Use the captured full object ID explicitly for the annotated tag while retaining
the existing displayed commit format and ADR-0236 release/version identity.
Require no concurrent source/output writers; rechecks cannot establish immutable
snapshot consistency against transient edit-and-revert activity.

Resolve the selected Git remote's single push URL to one explicit GitHub
host/repository. Use that destination consistently for tag lookup, push, and
GitHub commands. Require verifiable push access for draft visibility and a
complete successful paginated release lookup; errors or malformed results are
not absence. Preserve manual inspection after partial remote publication and do
not automatically remove refs. Restore caller location and process build
environment settings on every exit.

Remove only the release-script exclusion from the Codex changed-path checker;
normal exact Scope Ledger approval governs those edits. Retain every Fable
protection and the direct-to-main workflow. This changes checker enforcement,
not the static checker's inability to prove conversational authorization.

## Alternatives considered

1. Disable cleanliness or tidy checks: loses committed-source/module guarantees.
2. Delete outputs before preparing their replacement: loses prior artifacts on
   compilation failure and cannot establish ownership of unrelated contents.
3. Treat all GitHub lookup failures as missing releases: confuses permission,
   network, and malformed-response failures with absence.
4. Freeze source in another worktree for every release: provides stronger
   isolation but adds lifecycle and storage responsibilities beyond this fix.

## Consequences

### Benefits

- Preflight failures identify the operator action required.
- Failed preparation preserves existing files; replacement rejects deployment
  edits and runtime state even when filenames still match the generated tree.
- Release identity and destination stay consistent across Git and GitHub.

### Risks

- Legacy output migration requires manual inspection and moving old outputs.
- Ownership inventories and preparation consume temporary disk space.
- Concurrent source/output writers are unsupported; remote publication is not a
  transaction, and failed recovery may retain explicitly reported artifacts.

### Operational impact

The default Windows package names, public payload allowlist, release numbering,
runtime settings, and operator binary behavior remain unchanged. Maintainers
can run the script from another current directory because repository discovery
is anchored to the script. Custom outputs must satisfy the initial Git gate on
later runs. Use package-only builds and disposable fixtures to validate fixes;
real publication requires its own user authorization.
