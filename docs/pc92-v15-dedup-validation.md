## Implemented correction

Primary dedupe compares the original complete 42-byte encoding. Secondary
dedupe compares the original complete 32-byte encoding. The same low 32 bits of
xxh3 still select one of 64 shards. `Spot.Hash32` keeps its historical outputs
for its other callers. Minute/whole-kHz encoding, primary 15-byte calls,
secondary 12-byte DX calls, grid/CQ buckets, source classes, time windows,
out-of-order handling, stronger-report behavior, disabled-window semantics,
and client policy remain unchanged.

Primary cleanup evaluates expiry and removes entries under one continuous
shard lock. It no longer retains a proportional deletion list or deletes a
refreshed entry using a stale timestamp. The strict `age > window` condition
and existing compaction thresholds remain. The synchronous `cleanupAt` test
barrier is nil in production, retained nowhere, and runs under the actual
transaction lock. The test refreshes via real `processSpot`, both before
cleanup and concurrently while cleanup holds that lock.

The owned maps have the existing window-expiry lifetime; they introduce no
side index, worker, queue, or eviction policy. Existing `GetStats` exposes their
live cardinalities. Churn tests verify repeated insert/cleanup cycles return
live cardinality to zero. Compaction can temporarily own both map generations.
There is no newly asserted hard cardinality ceiling: input time, including
future timestamps, retains its existing meaning. This ordinary shared
ingestion state is reported separately from the peer 480-MiB envelope.
