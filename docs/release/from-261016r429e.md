## Before you upgrade

Stop the cluster before taking backups. Keep the old executable, its private
configuration, user profiles and preset libraries, and the archive and
grid-store data. Make your edits in a copy of the private configuration.
Deploy the new executable with the matching public reference files and point
`DXC_CONFIG_PATH` at the complete private copy. Keep your callsigns, endpoints,
credentials, and storage paths.

## Required operator actions

| Where | What to do | What happens if you skip it |
| --- | --- | --- |
| `runtime.yaml`, under `telnet` | Add `max_sessions_per_base_call: 10`, `max_sessions_per_ip: 10`, `command_rate_per_second: 5`, and `command_burst: 30`. Zero disables the corresponding station limit, IP limit, or pacing. The burst must still be positive. Review the IP limit if many stations share a router or proxy. | Missing or invalid settings stop startup. With the shipped limits, busy stations or shared addresses can reach their session limit, and fast command bursts can be paced. |
| `archive.yaml` | Add `bulletin_archive.path`. The example is `data/bulletins/history.json`. Use a writable location outside the spot archive's Pebble directory, even when spot archiving is disabled. | Missing or invalid configuration stops startup. The path is where the node retains independent WWV and WCY history. |
| `dedupe.yaml` | Add the complete `dedup.secondary_frequency_changes` block. Start with `state: off`, `cw_rtty_tolerance_hz: 500`, `ft_tolerance_hz: 3000`, `other_skimmer_tolerance_hz: 1000`, `human_tolerance_hz: 2000`, and `max_changes: 2`. If you customized `spot_policy.frequency_averaging_tolerance_hz` in `pipeline.yaml`, keep the CW/RTTY tolerance at least that high. | The new block is required even when off. Missing values, invalid states and invalid tolerances stop startup. |
| `path_reliability.yaml`, under `voacap_fallback` | Remove `recompute_delta_percent` and add `ssn_stale_after_seconds: 172800`. Review the shipped `ssn_ewma_half_life_seconds: 172800`, `forecast_hours: 24`, and `cache_ttl_seconds: 86400` if you carry forward the old values. | The retired key or a missing age setting stops startup. The age setting warns about old solar input. Forecasts now respond to changes in the rounded solar input. |
| H3 files and matching taxonomy | Verify that `h3_table_path` in `data.yaml` points to valid `res1.bin` and `res2.bin`. If you maintain a custom `spot_taxonomy.yaml`, reconcile it with the shipped copy before deploying. Also review any explicit Telnet event allowlist for the shipped addition of `SKIMMER`. | Missing or invalid H3 tables stop startup even when path prediction is disabled. Taxonomy and allowlists affect what the server recognizes and makes available to users. |
| `pipeline.yaml`, under `call_correction.bayes_bonus` | Set `enabled: false` and `enabled_distances_by_mode: {}` in your active private configuration to adopt the shipped inactive policy. | Installing the executable alone does not turn off the bonus in a private config that still enables it. Ordinary correction and the existing recent-report bonus remain active with the shipped settings. |

**Tell users their saved filters will reset.** The upgrade starts separate GO
and native CC filter banks from the node defaults. It resets older filters,
their six switches, and older named presets. Shared preferences and the
selected dialect carry forward. Use schema 7 CONFIG for a complete backup
after the move. Schema 6 represents only the older GO/settings interface.
Rollback requires the old executable and matching pre-upgrade profile and
preset backups. Restoring them discards changes made after the backup.

## Review for your node

- **Optional CW call rescue.** Keep `call_correction.selective_rescue_enabled`
  omitted or `false` to use ordinary correction. The shipped config sets it
  to `false`. [Call-correction evidence and bonus policy](docs/decisions/ADR-0360-call-correction-v2-evidence-and-bounded-bonuses.md) ·
  [Optional rescue behavior](docs/decisions/ADR-0361-selective-current-signal-call-rescue.md)
- **Custom login text.** Review your private `telnet.login_greeting` if you want
  the shorter shipped greeting. The new template uses `<LOGIN_SUMMARY>`,
  `<STARTUP_INFO>`, and `<UPGRADE_NOTICE>`. See the matching template in
  `runtime.yaml`. Restore your old template when rolling back to an executable
  that predates these tokens.
- **Frequency changes in skimmer spots.** With `state: off`, existing
  suppression continues. Use `shadow` to compare behavior without changing
  output. Turning it on can allow more reports through. The shipped Telnet
  broadcast batch interval also changes from 200 ms to 100 ms. Review that
  setting only if you want to adopt the new batching interval.
- **Logs and flood control.** Give each enabled log category its own folder so
  rotation can keep ownership clear. Review customized `floodcontrol.yaml`
  against the shipped file. The loader now checks all source tables, including
  inactive settings, and requires integer thresholds and valid ranges.
  Native automated reporters are exempt from the per-callsign quota and retain
  the other applicable limits. [Flood configuration troubleshooting](docs/troubleshooting/TSR-0133-flood-configuration-contract.md) ·
  [Native reporter quotas](docs/decisions/ADR-0353-native-reporter-quota-exemption.md)
- **IPinfo.** If enabled, use distinct snapshot/archive, metadata, and
  diagnostic CSV paths as described in the operator guide. A verified current
  local result takes precedence, and an eligible stale local result is the last
  fallback. The lookup cache limit covers both enrichment and Cymru records.
  [IPinfo verification and fallback](docs/decisions/ADR-0357-ipinfo-verification-and-download-integrity.md) ·
  [IPinfo troubleshooting](docs/troubleshooting/TSR-0136-ipinfo-and-download-integrity.md)
- **CTY and grid data.** Ship the matching CTY snapshot. The code fixes CTY
  coordinate conversion, exact callsign lookup, and how cached locator
  information interacts with the current CTY snapshot. If rebuilding the grid
  store to retire old estimates, follow the documented stopped-service backup
  and recovery procedure. An empty store temporarily loses valid historical
  locator coverage. [CTY and grid decision](docs/decisions/ADR-0340-cty-grid-authority.md) ·
  [Grid rebuild procedure](docs/runbooks/cty-grid-rebuild.md)

## What users will notice

- **Telnet.** The default login greeting and HELP are shorter. Plain `NEXT`
  continues an archive search, while coded continuation still works. The
  updated native CC bank, fixed meta-band shortcuts, CW speed display, and CC11
  output expand what compatible clients can request or show. Review client
  integrations before cutover if they consume structured output or depend on
  specific login text. [Archive paging](docs/decisions/ADR-0359-plain-next-for-telnet-history.md) ·
  [Meta-band membership](docs/decisions/ADR-0356-fixed-meta-bands-and-shared-physical-catalogue.md) ·
  [CC11 output](docs/decisions/ADR-0351-native-cc11-output-port.md)
- **Spot intake and peer forwarding.** Human report comments and signed signal
  values have clearer parsing rules. Peer flood control applies the same
  verdict to local handling and onward forwarding of the original report.
  [Human report rules](docs/decisions/ADR-0349-human-explicit-report-and-rejection-diagnostics.md) ·
  [Peer flood behavior](docs/decisions/ADR-0354-peer-flood-verdict-and-retirement.md)
- **Custom SCP.** The capacity fix avoids a
  full scan to choose an entry for eviction. It requires no YAML edit.
  `max_db_bytes` is a legacy setting and does not limit disk usage.
  [Custom SCP design](docs/decisions/ADR-0358-custom-scp-capacity-index.md) ·
  [What to monitor at capacity](docs/troubleshooting/TSR-0137-custom-scp-capacity-eviction-and-pebble-ownership.md)
